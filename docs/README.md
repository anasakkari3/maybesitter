# Documentation map

Where each document belongs, and which one wins when two disagree. Files are
not moved between tiers: tests, ADRs and specs link to their current paths.
Instead, this map says how to read each folder.

## Order of authority

1. **`AGENTS.md`** (repository root), then **`mobile/AGENTS.md`** for the app.
   Engineering rules, invariants, test conventions, the skill routing policy.
2. **`docs/strategy/CURRENT_PRODUCT_STRATEGY.md`** — what the product is and
   is not doing now (NARROW AND TEST). Overrides any roadmap or spec below.
3. **`docs/architecture/`** — ADRs (`adr-*.md`) and boundary documents.
   An ADR stands until a later ADR supersedes it. The Stage B Build Gate /
   Release Gate split is `adr-stage-b-engineering-unlock.md`.
4. **`docs/operations/DEPLOY.md`** — how the backend reaches staging and
   production, and the current isolation status. Other operational runbooks
   in `docs/operations/` apply to the release named in their title.
5. Contracts in code (`src/contracts/v1/`) and the tests that enforce them
   override any prose that describes them.

## Recovery records (2026-10-26 → 2026-11-08)

The repository recovery reports (Phases 3–5.8 and the final report) are kept
outside the repository, with the backups they describe, in
`~/MaybeSitter-recovery-backups/`. The workspace root holds
`MAYBESITTER_RECOVERY_FINAL_REPORT.md`.

## Adding a document

Put it in the folder whose row above describes it. If it replaces an older
document, say so in its first lines and add the older one's path. Dated
session notes, agent state files and debugging output do not belong in
`docs/`.
